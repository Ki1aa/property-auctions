# MVP product contract

Дата ревизии: 2026-05-10.

## Цель MVP

MVP - это не полноценная платформа оценки недвижимости, а рабочий Telegram-first монитор земельных лотов. Он должен автоматически находить новые и изменившиеся лоты ГИС Торги по ИЖС/ЛПХ/садоводству в Тюмени и Тюменской области, выделять конкретный участок внутри извещения, давать первичную цену за сотку и быстро вести пользователя к проверке источников.

Главная бизнес-метрика MVP: пользователь открывает Telegram-уведомление и за 1-3 минуты понимает, стоит ли лот смотреть глубже.

## Пользовательский сценарий

1. Backend по расписанию забирает OpenData ГИС Торги и detail JSON извещений.
2. Сервис отсекает нецелевые имущественные лоты: автомобили, древесину, помещения и прочее, оставляя земельные участки / права на земельные участки.
3. Если в извещении несколько `notice.lots[]`, сервис создаёт отдельную карточку на каждый внутренний лот.
4. Сервис фильтрует/маркирует ИЖС-кандидатов по коду ВРИ и текстовым fallback'ам.
5. Сервис считает стартовую цену за сотку и внутренний baseline по уже загруженным торгам.
6. Telegram отправляет компактное уведомление по `new_lot` / `changed_lot`.
7. Пользователь открывает ссылки: монитор, ГИС Торги, НСПД-карта, поиски на площадках.

## Контракт Telegram-уведомления

Сообщение по лоту должно содержать:

- событие: новый лот или изменение;
- короткий вердикт: интересно / проверить вручную / низкий приоритет;
- причины вердикта: ИЖС-признак, наличие кадастра, дисконт к baseline;
- заголовок лота, регион, муниципалитет, населённый пункт;
- кадастровый номер, площадь, категория земли, ВРИ и коды ВРИ;
- стартовую цену, текущую цену, стартовую цену за сотку и за м²;
- baseline за сотку, дисконт, confidence и честное пояснение, что это пока не рыночная оценка Циан;
- даты начала и окончания;
- ссылки: монитор, ГИС Торги, raw JSON ГИС Торги при необходимости, НСПД-карта, опциональные поиски Циан/Авито/Домклик.

Важная формулировка: ссылка ГИС Торги ведёт на публичное извещение, а не на отдельный внутренний `notice.lots[]`. Наш монитор обязан показывать `regNum + lotNumber`, чтобы пользователь понимал, какой именно участок смотреть внутри извещения.

## Контракт ссылок

- **Монитор:** внутренняя карточка `/lots/{id}` - главный рабочий экран по конкретному участку.
- **ГИС Торги:** `https://torgi.gov.ru/new/public/notices/view/{regNum}` - официальный публичный экран извещения. Если HTML-ссылка недоступна, fallback - raw JSON.
- **Raw JSON ГИС Торги:** detail JSON из OpenData - техническая проверка полей и multi-lot структуры.
- **НСПД-карта:** при наличии `nspd_card_id + nspd_card_type + centroid` ссылка собирается как deep link с `selectedCard`, координатами и zoom. Если id карточки ещё нет, ссылка открывает НСПД-карту в районе центроида и добавляет кадастровый номер в query; если нет и центроида, открывает НСПД-карту с кадастровым номером в query.
- **Домклик-карта района:** если у лота есть координаты или НСПД-центроид, сервис строит bbox вокруг участка и открывает `search/on-map` с `offer_type=lot`. Это быстрый ручной экран цен рядом, не автоматическое сопоставление.
- **Циан/Авито/Домклик в MVP:** текстовые поисковые ссылки по кадастру или адресу. Это не доказательство совпадения и не рыночная оценка.

## Сопоставление с агрегаторами

В MVP поиск на агрегаторах - это ручной ускоритель, а не автоматический matching. Следующий слой должен разделять две разные задачи:

1. **Найти тот же участок:** точное совпадение по кадастровому номеру. Если кадастр опубликован в объявлении, confidence близок к 1.0.
2. **Найти рыночные аналоги:** участки рядом, похожие по площади, назначению, локации и статусу коммуникаций. Это не тот же участок, но база для оценки рынка.

План matching-логики:

- нормализовать каждое объявление в `MarketComparable`: источник, URL, цена, площадь, цена за сотку, кадастровый номер при наличии, адрес, координаты/геометрия, дата сбора, сырой payload;
- exact-match: `cadastral_number` совпал с лотом ГИС Торги;
- strong analog: расстояние до центроида НСПД в пределах заданного радиуса, площадь в допустимом диапазоне, тот же муниципалитет/населённый пункт, похожий ВРИ;
- weak analog: текстовый адрес/посёлок совпадает, площадь и цена пригодны, координат нет;
- valuation: медиана цены за сотку по strong analog, диапазон p25/p75, sample size, confidence;
- investment signal: `discount_to_market`, качество кадастра, ликвидность локации, сроки подачи заявки и риски данных.

## Что уже считается готовым для MVP

- ingest ГИС Торги через OpenData и detail JSON;
- продуктовый фильтр земельных лотов (`INGEST_ONLY_LAND_LOTS=true`);
- multi-lot split: один `notice` может дать несколько карточек `Lot`;
- ИЖС-кандидат по коду ВРИ и fallback-тексту;
- `notice_reg_num`, `notice_lot_number`, `notice_lot_count` в API/UI;
- внутренний baseline по загруженным торгам;
- Telegram-алерты с дедупликацией и ссылками;
- опциональный НСПД enrichment при `NSPD_ENABLED`;
- Домклик-карта вокруг участка при наличии координат/НСПД-центроида;
- поисковые ссылки на Циан/Авито/Домклик при `INCLUDE_MARKETPLACE_SEARCH_URLS=true`.

## Не обещаем в MVP

- автоматическую рыночную оценку по Циан/Авито/Домклик;
- гарантированный deep link на конкретный внутренний лот в публичном UI ГИС Торги;
- гарантированную карточку того же участка на агрегаторах;
- investment_score как production-сигнал.

## Ближайший порядок работ

1. Подобрать production-настройки Telegram-фильтров на живом потоке: ИЖС, кадастр, минимальный дисконт, strict baseline при достаточной базе.
2. Прогнать live ingest по Тюменской области на машине с российским маршрутом.
3. Проверить НСПД enrichment на 20-50 кадастровых номерах и зафиксировать coverage.
4. Выбрать первый источник аналогов, предпочтительно Циан, и заполнить `MarketComparable`.
5. После первых аналогов заменить внутренний baseline в Telegram на честную рыночную оценку или показывать оба значения рядом.
